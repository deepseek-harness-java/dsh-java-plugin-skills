# 案例储备智能体应用 Prompt

用途：用户没有明确应用诉求时，从这里抽 **3~5 个跨分类案例**（完整话术，非标题）展示给用户；用户选定（或原样粘贴）后，按该话术直接走 SKILL.md 工作、部署。每个 prompt 均运行，无需补充信息（端口、数据、技术栈等按 SKILL处理）。

## 场景深挖（选定案例后、写码做）

一句话 prompt 是需求输入，**开发前必须深挖成设计稿**，禁止拿到 prompt 直接写码：

1. **实体表**：列出核心实体及段（照下方深挖卡片，或按公式推导）。要够渲染真实页面（如商品：名称/价格/分类/标签/库存/封面渐变色）
2. **工具表**：每个"列表+详情"工具，写清每个工具的入参/出参 JSON 结构和 description（何时必须调用）
3. **页面区块**：hero（大标题+主行动按钮+统计数字）→ 列网格 → 详情/表单 → AI 助手面板；管理台型则： + 数据看板 + 表格 + 操作栏
4. **预置数据**：按 prompt 中规模预置，数据要"像真的中文业务文案、合理价格区间、分布在不同分类）
5. **参照标杆**（可 WebFetch 抓 README 验证业务结构）：电商类参照 [mall](https://github.com/macrozheng/mall)（商品/订单/营销/会员四模块）；UI 组件参照 50projects50days；本技能两个案例源码是最直接的完整实现

## 使用规则

1. **用户问"能做什么/举个例子"** → 按下面分类轮换抽 3~5 个（跨大分类），原话术展示，并说明"选定任意一个即可一句话完成开发+部署启动运行"
2. **用户粘贴/改写其中一个** → 该 prompt 即为需求输入，直接进入阶段 0（唯一要确认的只有"新开发 or 对接已有应用"）
3. **用户领域不在库中** → 参照同分类句式即时生成一个同结构 prompt（业务实体 + 5 个 AI 工具 + 前端 + AI 助手 + 交付），同样一句话可执行
4. 展示时附上对应"AI 能力亮点"，这个案例做出来是什么样

## Prompt 结构公式（用于生成库外案例）

```
开发一个 PC 端 <领域应用>，
含 <核心功能 3~4 项>，预置 <演示数据规模>；
AI <角色名>助手能 <3 个跨工具的智能能力>，
<以插件接入 DSH 运行 / 启动运行给我地址>。
```

生成时保持：**业务实体明确**（便于列实体→设计工具）、**AI 能力必须跨工具联动**（体现智能体价值，而非单查询）、**演示数据有规模**（页面不空）。每个案例默认交付：DSH 8090 + 应用地址 + 插件工具清单 + 使用说明。

## 细腻度规范（防"路线A/路线B"式敷衍，生成后逐条验收）

一句话 prompt 定不了细腻度，细腻度靠**数据样本标尺 + 验收清单**保证。写预置数据前先读这节；生成的应用对照清单逐条自检，任何一条不过就重做数据，不交"占位符产品"。

### 一、数据样本标尺（照这个密度写，各领域举一反三）

**差（禁止）** vs **好（必须）** 对照：

```text
✗ 路线A：名称"自然科考路线"，价格 3000，3 天
✓ 云南高黎贡生物科考营：名"遇见滇金丝猴·高黎贡生物科考 5 日营"，
  适合年龄 9-14 岁，¥5,980/人，7 月 12 日/7 月 26 日两期各剩 6/11 位，
  亮点"红外相机布设实操 + 长臂猿鸣声记录 + 中科院研究员随营"，
  D1 抵达保山·营地安全 D2 滇金丝猴栖息地监测 → D3 夜行性动物观察…

✗ 商品A：名称"手机"，价格 999
✓ 「星尘 X7 Pro」5G 旗舰，12GB+512GB 深空灰，¥4,299，
  库存 37，标签"旗舰芯 影像旗舰 / 12 期免息"，
  卖点文案"2 亿像素主摄，暗光成片率提升 40%"

✗ 医生A：内科张医生
✓ 林晚晴 · 心血管内科 · 主任医师 · 从业 18 年，
  简介"擅长高血压、冠心病个体化诊疗与心脏康复管理"，
  本周三/五上午门诊，余号 3/7 个

✗ 工单A：标题"系统报错"
✓ 【P1】"核心支付回调超时率 3.2%，影响微信渠道订单"，
  提交人 王倩，指派 陈立（支付组），已处理 2h，
  时间线：16:02 告警触发 → 16:10 定位网关超时 → 16:45 降级预案生效
```：**名称有品牌/地名/编号、价格符合真实区间、数量有余有缺（别全是整数）、日期具体到日、文案有行业术语和数字**。中文数据一律写真实业务感中文，禁止 lorem ipsum、"测试数据"、"示例"字样出现在页面上。

### 二、文案样本（hero、空态、按钮、AI 气泡）

- Hero：`这个暑假，把孩子交给大自然` ＋ 副标 `中科院研究员随营的 12 条科考路线，正在报名`（不是"欢迎来到研学平台"）
- 空态：`7 月的营位已经报满啦，8 月路线即将看看往期路线过过瘾` ＋ 按钮「看往期路线」（不是空白或"暂无数据"）
- 按钮：动词开头带场景——「选这个排期」「加入购物车」「发起拼团」（不是「确定」「提交」「OK」）
- AI 气泡开场：`你好呀～想给孩子找哪个方向的营地？科考、人文还是编程？告诉我年龄和兴趣，我帮你挑几条 👇`（不是"您好，请问有什么可以帮您？"）

### 三、细腻度验收清单（生成完逐条过，任一不过 = 不合格重做）

1. **数据密度**：每条核心数据 ≥ 6 个有意义字段；列表页首屏能看出"这是个真产品"
2. **数据间有故事**：数据互相咬合——有满员的排期也有剩 2 位的排期；有已完成订单也有配送中的订单；用户 A 的点评引用了商品 B。禁止所有记录同质化
3. **文案零占位**：全站搜索不到"示例/测试/XXX/xxx/Route A/商品A"
4. **数字有算术合理性**：订单金额=商品价格×数量；拼团进度=已拼/总人数；统计数字与明细加总一致
5. **状态机完整**：核心实体有 ≥3 种状态且都能在预置数据中看到（待支付/已支付/已完成/已退款各至少 1 条）
6. **AI 回答有据**：让 AI 助手查任何一个工具，返回的数据在页面上能找到对应（工具查的就是预置数据，不是现编）
7. **移动端不塌**：缩到 375px 宽无横向滚动、卡片单列、导航可用

### 四、库外案例同样执行

用 Prompt 结构公式生成库外案例时，交付前必须按本节清单验收；案例 prompt 本身不写数据细节没关系，**细腻度由本规范兜底**，不依赖用户把 prompt 写得多细。
